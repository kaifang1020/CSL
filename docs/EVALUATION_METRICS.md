# 数字患者头像 — 综合评估指标体系

> 目的:给"实时反应式数字患者头像(AvatarForcing 自建引擎)"建立一套**可操作、可复现**的质量评估体系。
> 每个指标写清:**① 测什么 ② 具体怎么算(公式/算法)③ 要不要 ground truth ④ 用什么工具 ⑤ 怎么解读**。
> 配套:速查阅读地图见 [EVALUATION.md](EVALUATION.md);漂移根因见 [DRIFT_ANALYSIS.md](DRIFT_ANALYSIS.md);系统架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

---

## 0. 评估哲学(先立框架,再谈指标)

### 0.1 生成 ≠ 重建
我们的头像是**生成**的(给一张脸 + 音频 + 治疗师动作,合成一段全新视频),不是去**重建**某段已知的真人视频。所以:
- **不能**简单地"逐帧对比生成帧 vs 某个标准答案帧"——因为根本没有唯一正确答案(患者点头的时机、幅度都可以不同却都合理)。
- 真人 GT 视频应当作**分布**(FID/FVD 用)或**参照**(身份、风格),而不是**逐帧答案键**。
- 逐帧 LPIPS-vs-GT 这类"成对"指标只在**有对齐 GT 的重建任务**里才严格成立;在纯生成里要谨慎。

### 0.2 按"有没有 Ground Truth"三分类(决定能测什么)
| 类 | 定义 | 例子 | 我们的处境 |
|---|---|---|---|
| **A. 成对 GT** | 有逐帧对齐的真人答案 | LPIPS、SSIM、头姿误差、rPCC | 需要 dyadic(双人)录制;我们缺 |
| **B. 分布级 GT** | 有真人视频当"真实分布",不需逐帧对齐 | FID、FVD | 32 个真人 clip **解锁了这一类** |
| **C. 无 GT / 参照 / 对比** | 只需参考脸,或跟自己/SOTA 比 | CSIM、锐度、抖动、LSE、人评偏好 | **现在就能测**,是主力 |

> 结论:**C 类现在全能测,B 类靠 32 clip 能测,A 类缺 dyadic GT 暂时受限。** 下面每个指标都标了类别。

### 0.3 三个时间尺度(实时系统特有)
1. **帧级(40ms / 25fps)**:单帧清晰度、身份、抖动。
2. **回合级(~1–3s)**:一句话的口型同步、首帧延迟、反应及时性。
3. **会话级(分钟)**:漂移累积、多轮语义连贯、情感轨迹。
> 很多指标必须**沿时间画曲线**才有意义(见 §7),单点均值会掩盖"聊久了才崩"。

## 1. 身份保持 / 漂移(Identity & Drift)⭐ 我们的核心问题

### 1.1 CSIM(Cosine Similarity of Identity)— 类别 C
- **测什么**:生成帧里的人脸,和**参考脸**(或真人 GT)在身份上有多像。直接量"还是不是这个人"。
- **怎么算**:
  1. 用人脸识别网络(**ArcFace**,`insightface` 的 `buffalo_l`)把每张脸编码成 512 维**归一化嵌入** `e`。
  2. 参考脸嵌入 `e_ref`,第 t 帧嵌入 `e_t`。
  3. `CSIM(t) = e_ref · e_t`(两个单位向量点积 = 余弦相似度),范围约 [-1, 1],越高越像。
- **要 GT?**:不需要——对**参考脸**算即可(也可对真人 GT 算)。
- **工具**:`insightface`(我们的 `sweep_csim.py` / `eval_gt.py`)。
- **怎么解读**:
  - 单帧值:>0.8 很像,~0.5 开始不像,<0.4 基本崩了。
  - **关键是画成"CSIM–时间"曲线**——这条曲线就是**漂移曲线**(见 §7)。
- **实测例**(60s 倾听压力测试,u_cfg=1.0):原版 μ=0.55、末端掉到 0.31(崩塌);加 pose 正则 λ=0.2 后 μ=0.91、末端 0.90(几乎不漂)。

### 1.2 漂移斜率(Drift Slope)— 类别 C
- **测什么**:身份**随时间流失的速度**——把"聊久了会不会越来越不像"量化成一个数。
- **怎么算**:对 `CSIM(t)` 做**线性最小二乘拟合** `CSIM ≈ a·t + b`,斜率 `a` 再乘 10 → **每 10 秒的 CSIM 变化量**。
- **解读**:≈0 = 稳;负得越多漂移越快。**实测**:原版 −0.116/10s(单调下滑),pose 正则 λ=0.2 是 −0.001/10s(基本水平)。
- **意义**:这是区分"pose 正则真的压平曲线"vs"u_cfg 只是延后崩塌"的关键指标——斜率变了才叫根治。

## 2. 时序稳定性 / 抖动(Temporal Stability)⭐ 现在在攻的问题

### 2.1 tremor_hf(高频震颤)— 类别 C 【本项目自建,对得上肉眼"发抖"】
- **测什么**:头部/五官的**高频小幅震颤**——就是肉眼看到的"脸在抖/头在颤",区别于"慢慢漂移"。
- **怎么算**(关键是**分离高低频**):
  1. 每帧用 `face_alignment` 检 68 个关键点,取**质心**(头部中心)得到轨迹 `c(t)`(2D)。
  2. 对每个坐标轴做**滑动均值**(窗口 ~0.5s=12帧)`ĉ(t)` = 慢分量(漂移)。
  3. **高频残差** `r(t) = c(t) − ĉ(t)`(减掉慢漂移,只剩抖)。
  4. `tremor_hf = RMS(|r(t)|) / 双眼间距 × 1000`(按双眼距归一化 → 尺度无关,单位‰)。
- **要 GT?**:不需要。**工具**:`jitter_hf.py`(GPU/face_alignment)。
- **解读**:越低越顺。**实测**(60s,u_cfg=1.0):原版无正则=21.0;pose 正则 λ=0.1=7.3(降 65%);再叠时序平滑 EMA 只降到 6.2(边际很小 → 说明剩余震颤在解码器/合法微表情里,推理期平滑治不动)。
- **为什么要专门设计它**:普通"帧间位移"均值会被"大幅乱飘(崩塌)"主导,反而抓不住"小幅有节律的抖"。先高通滤波再算 RMS 才对得上感知。

### 2.2 v1_jitter(帧间关键点位移)— 类别 C
- **测什么**:相邻两帧所有关键点平均移动了多少(总体运动能量,含漂移+抖+合法动作)。
- **怎么算**:`v1 = mean_t( mean_k |k_t − k_{t-1}| ) / 双眼距 × 1000`。
- **解读**:粗指标,擅长抓"大幅乱飘/崩塌",不擅长抓"节律性震颤"(所以才要 §2.1)。两者一起看。**实测**:原版 29.4,加正则后 ~10–11。

### 2.3 FVD(Fréchet Video Distance)— 类别 B ⭐ 视频级金标准
- **测什么**:**整段视频**(含时序动态)和真人视频分布的距离——同时惩罚"单帧假"和"时序不连贯/漂移/闪烁"。
- **怎么算**:
  1. 用预训练 **I3D**(视频动作识别网络)把每段视频(通常 16 帧一窗)编码成特征向量。
  2. 分别对"生成集"和"真人集"的特征估**多元高斯** `N(μ, Σ)`。
  3. `FVD = |μ_g − μ_r|² + Tr(Σ_g + Σ_r − 2(Σ_g Σ_r)^{1/2})`(两个高斯的 Fréchet 距离)。
- **要 GT?**:要**分布级**(一批真人视频,不用逐帧对齐)→ 32 clip 够用。
- **工具**:StyleGAN-V 的 FVD 实现。**解读**:越低越好;对我们**时序稳定性/漂移**最敏感。

### 2.4 VDE(Video Drift Error)— 类别 C
- **测什么**:长视频生成里专门量"随时间偏离初始状态"的指标(长视频扩散文献)。和 CSIM 漂移斜率互补,可作旁证。

## 3. 视觉保真度(Visual Fidelity)

### 3.1 FID(Fréchet Inception Distance)— 类别 B
- **测什么**:**单帧**真实度(和真人单帧分布的距离)。不含时序。
- **怎么算**:同 FVD,但用 **InceptionV3** 图像特征(2048 维),对生成帧集 vs 真人帧集算两个高斯的 Fréchet 距离。
- **工具**:`pytorch-fid` / `clean-fid`。**解读**:越低越真;抓"整体画质/纹理是否像真人",但对身份/时序不敏感(要配 CSIM/FVD)。

### 3.2 锐度 / 模糊度(Sharpness,Laplacian 方差)— 类别 C ⭐
- **测什么**:画面**糊不糊**。
- **怎么算**:对每帧(或脸区)算**拉普拉斯算子响应的方差** `Var(∇²I)`——边缘越锐,高频能量越大,方差越高。
- **工具**:`cv2.Laplacian(img, CV_64F).var()`(我们的 `eval_gt.py`)。
- **解读**:越高越清晰。**沿时间画曲线**能看到"聊久了变糊"。更严格可用 **CPBD**(Narvekar 2011,感知模糊)。

### 3.3 LPIPS(感知相似度)— 类别 A(成对)
- **测什么**:两张图的**感知**差异(比 L2 更贴近人眼)。
- **怎么算**:把两图各喂 AlexNet/VGG,取多层特征,逐层做通道归一化后算加权 L2,`LPIPS = Σ_l w_l · ||φ_l(x)−φ_l(y)||²`。
- **两种用法**:
  - **成对 vs GT**(类 A,需对齐 GT):量"离真人多远"——纯生成里慎用(见 §0.1)。
  - **相邻帧 LPIPS**(类 C,无 GT):当**时序平滑度**指标(帧间感知跳变),越低越顺。
- **工具**:`lpips`(pip)。

### 3.4 SSIM / PSNR — 类别 A
- **测什么**:结构/像素相似度。**要对齐 GT**。非感知,重建任务常用,生成里仅作参考。

## 4. 口型同步(Lip-sync)

### 4.1 LSE-C / LSE-D(Lip-Sync Error - Confidence / Distance)— 类别 C
- **测什么**:嘴型和音频**同步得好不好**(说话时对不对口型)。
- **怎么算**:用 **SyncNet**(Chung 2016,Wav2Lip 采用)——一个把"嘴部视频片段"和"音频片段"分别编码、学它们该不该对齐的网络:
  - **LSE-D**:音视频嵌入的距离(越小越同步)。
  - **LSE-C**:正确对齐相对错位的置信度(越大越同步)。
- **要 GT?**:不需要(SyncNet 自带判据)。**工具**:Wav2Lip repo 的 eval。**解读**:数字患者说话时口型可信度的客观量。

### 4.2 LMD(Mouth Landmark Distance)— 类别 A
- 嘴部关键点对 GT 的误差,需对齐 GT。

## 5. 反应性(Reactiveness)— 数字患者的灵魂,但需 dyadic GT

> 我们的患者是**反应式**的(听治疗师说话时会点头、皱眉、看你)。这类"反应对不对"的指标最难,因为需要**双人(dyadic)真人对话录制**当 GT。

### 5.1 rPCC-Exp / rPCC-Pose(residual Pearson Correlation Coefficient)— 类别 A
- **测什么**:患者的表情/头姿变化,和"真人在同样刺激下"该有的反应,**相关性**有多高。
- **怎么算**(概念):
  1. 用 **EMOCA / 3DMM** 把每帧脸拟合成参数:表情系数(Exp)、头姿(Pose)。
  2. 对生成序列和真人 GT 序列,各自**减掉均值/身份基线**得残差(只留"动态变化")。
  3. 算两条残差序列的 **Pearson 相关系数**;Exp 和 Pose 分开。
- **要 GT?**:**要 dyadic GT**(同一治疗师输入下的真人反应)——我们暂缺。
- **意义**:这是真正衡量"反应像不像真人"的指标;没有 dyadic GT 时,只能退而用 §5.2 + 人评。

### 5.2 运动丰富度 / 多样性(Motion Richness:SID / Var / Diversity)— 类别 C
- **测什么**:反应**够不够活**(不是僵脸,也不是乱动)。
- **怎么算**:对表情/姿态参数序列算**方差**、**时间上的标准差 SID**、或多样性(不同时段动作的分布散度)。
- **解读**:太低=僵/死;太高=乱/不自然。**和 CSIM 一起看**能抓"pose 正则/EMA 调太狠把反应压没了"的副作用(稳但僵)。

## 6. 延迟与流畅(Latency & Fluency)— 实时系统特有,离线 paper 少谈

### 6.1 分组件 TTFB(Time To First Byte / First Frame)
- **测什么**:治疗师说完到患者开始回应的**首字节/首帧延迟**,拆到每个组件。
- **怎么算**:在管线各处打时间戳,报 **STT → LLM → TTS → Avatar** 各自的 TTFB,以及**端到端总延迟**。
- **工具**:我们前端 `index.html` 的状态面板已经在显示 `component_ttfb`。
- **解读**:交互体验的命门。总延迟 >2–3s 就会明显"卡"。

### 6.2 实时倍率 / 每块延迟
- **实时倍率** = 生成时长 / 视频时长(需 >1× 才跟得上实时)。**每块延迟** = 生成 10 帧要多少 ms。
- **实测**(bench):~186–229ms/块,1.75–2.15× 实时(4090)。

### 6.3 掉帧率 / 队列深度 / 卡顿
- **测什么**:25fps 播放能不能稳住;队列空了会冻结(重复上一帧)。
- **怎么算**:统计队列深度=0 的比例、实际输出 fps、冻结时长占比。
- **注意**:显存不足会导致生成崩溃→冻结(我们实测遇到过 OOM 叠加多会话)。

### 6.4 启动 / 首帧冷启动延迟
- 连接到出第一帧的时间(模型加载 + 首块冷生成)。首块通常比后续块慢(无 KV cache)。

## 7. 时间维度(Time Dimension)⭐ 你特别强调的

> 核心主张:**单点均值会骗人**。很多问题(漂移、变糊、累积误差)是"聊久了才发作"。所以几乎每个视觉指标都应该有**时间版本**。

### 7.1 vs-时间曲线
- 把 **CSIM / 锐度 / tremor_hf / LPIPS(相邻帧)** 都画成"值–时间"曲线,而不只报均值。
- 我们的 `sweep_csim.py`(CSIM 曲线叠图)、`eval_gt.py`(CSIM/锐度/抖动三曲线)就是干这个。

### 7.2 漂移起始时间(Drift Onset / Time-to-Threshold)
- **测什么**:撑多久才开始崩。
- **怎么算**:CSIM 首次跌破阈值(如 0.6)的时间点。**实测**:原版 u_cfg=1.0 约 15s 起崩;调 u_cfg=0.3 能拖到 ~30s;pose 正则则全程不破。

### 7.3 恢复行为(Recovery / Oscillate-and-recover)
- 有些配置是"抖一下又回来"(说话模式:振荡-恢复),有些是"单调下滑不回头"(倾听崩塌)。曲线形状本身就是诊断。

### 7.4 会话时长阶梯压测
- 固定测 **10s / 30s / 60s / 5min** 多档,看指标随时长退化的曲线——比只测一个时长可靠。

### 7.5 跨回合累积(Cross-turn drift)
- 多次"说话→倾听"切换后,残余漂移会不会累积?(和 §8 多轮连贯相关,但这是**视觉**层的累积。)

## 8. 多轮语义连贯(Multi-turn Semantic Coherence)⭐ 你强调的 —— 这是"大脑"层,不是"脸"层

> 数字患者不止要"脸对",还要"作为一个人前后一致"。这层评的是 **LLM/persona/状态**,视频指标测不到,但对"数字患者"可信度至关重要。和你的 [患者状态动力学](../patient-state-dynamics) 工作直接相关。

### 8.1 人设一致性(Persona Consistency)
- **测什么**:多轮下患者是否**稳定保持人设**(身份、背景故事、说话风格)。
- **怎么算**:LLM-judge 打分(给评分量表 rubric)+ 事实一致性检查(是否自相矛盾:年龄、经历、关系)。

### 8.2 情感轨迹连贯(Affective Trajectory Coherence)
- **测什么**:情绪状态是否**平滑、可信地演变**(不该这句崩溃下句没事);对应你把"状态漂移"建模成动量-SGD 追踪移动目标的思路。
- **怎么算**:沿时间记录状态量(guardedness / grief / alliance)→ 看轨迹是否单调/平滑/对治疗师干预有合理响应;可用状态曲线 + 突变检测。

### 8.3 记忆 / 指代消解(Memory & Reference Resolution)
- **测什么**:后面能不能**回指前面**披露的信息("你刚说的那件事…")。
- **怎么算**:设计探针对话(前面埋信息,后面问),测召回正确率。

### 8.4 反串防护(Anti-role-flip)⭐ 我们踩过的真 bug
- **测什么**:患者**绝不能说治疗师的台词**(在自杀等敏感内容上尤其会破功)。
- **怎么算**:自动检测"患者话轮里出现治疗师式引导语"的发生率;人工抽检。**这是安全项,发生率应趋近 0**。

### 8.5 话轮衔接 / 相关性
- 回应是否**接得上**上一句(相关性)、有没有答非所问、重复、跳戏。可用 LLM-judge + 语义相似度。

## 9. HCI / 人类主观评估(Human Evaluation)— 类别 C(对比/主观)

> 客观指标测不全"自然不自然",最终要人来评。**尤其没有 dyadic GT 时,人评 + 对 SOTA 的偏好是主力。**

### 9.1 MOS(Mean Opinion Score,1–5)
- 分维度打分:**自然度 / 身份保真 / 口型同步 / 表情可信 / 整体真实感**。多评委取均值 + 置信区间。

### 9.2 对 SOTA 的成对偏好(Pairwise Preference)
- **和闭源/开源 SOTA 并排比**:Simli(我们原来的)、Tavus、HeyGen、EMO 等。
- **怎么做**:同一输入生成两版,盲评"哪个更自然/更像患者",统计胜率。**这是"无 GT 时"最有说服力的证据。**

### 9.3 恐怖谷 / 可信度(Uncanniness)
- 专门问"有没有诡异感";数字人容易踩恐怖谷。

---

## 10. 临床 / 领域特异(Clinical / Domain-specific)— 我们是临床训练场景,这层别人 paper 没有

### 10.1 情感状态保真(Affective Fidelity)
- **测什么**:患者表情是否**匹配设定的临床情感**(戒备、悲伤可及性)。把"意图情感"和"实际呈现"对齐。
- **怎么算**:用 AU/情感识别读生成脸的情感,和剧本设定/状态量对比。

### 10.2 临床真实性(Clinical Realism)
- 由临床专家评:这个患者的**行为/反应符不符合该病例**(如抑郁患者的语速、回避、平淡情感)。

### 10.3 训练效能(Downstream Training Efficacy)⭐ 终极指标
- **测什么**:用这个数字患者训练,学员的临床技能**是否真的提升**(vs 传统标准化病人)。
- **怎么算**:前后测、OSCE 评分、与真人标准化病人对照实验。这是整个项目的**终极价值指标**。

### 10.4 安全 / 场景保持(Safety)
- 患者**不脱离场景、不产生有害内容**;敏感话题(自杀意念是合法临床训练内容)处理得当、不破功、不给出危险建议。发生率应为 0。

## 11. 我认为还需要考虑的维度(补充建议)

1. **跨模态一致性(Cross-modal consistency)**:说话的**语音情感**和**面部情感**对不对齐(声音悲伤但脸在笑=出戏)。可用 SER(你有 ser.py)+ 面部情感联合评。
2. **公平性 / 跨脸鲁棒性(Fairness across faces)**⭐:模型会不会**对某些肤色/发型/面部特征退化更严重**?——Candice 是深肤色卷发,这点**必须专门测**(在不同真人脸上跑同一套指标,看方差)。这是伦理+质量双重要求。
3. **失效模式分类与发生率(Failure taxonomy & rate)**:把"融化/冻结/口型脱节/闪烁/伪影"分类,统计**每分钟发生率**——比单个连续指标更能指导修 bug。
4. **输入扰动鲁棒性(Robustness)**:摄像头差、光线暗、长时间静音、频繁打断、网络抖动时,画质/反应如何退化。
5. **计算成本作为一个评估轴(Efficiency)**:显存峰值、$/小时、能耗、可支撑并发会话数。我们实测过"每会话叠 ~15GB、24GB 卡只够 1 路"——**并发容量本身是个要报告的指标**。
6. **可复现性 / 确定性(Reproducibility)**:同输入同种子出同结果吗?对做实验对照很重要。
7. **交互时序质量(Turn-taking)**:抢话/打断/沉默填充是否自然(不只是延迟数字,还有对话节奏)。

### 建议的测量顺序
1. **先把 C 类批量化**:对 32 clip(换脸生成)+ 多档时长,自动跑 CSIM/tremor_hf/锐度/LSE,出"指标–时间"曲线库。
2. **B 类加上**:FID/FVD 给出分布级真实度,建立和 SOTA 的可比基线。
3. **人评 + 对 SOTA 偏好**:补客观指标测不到的"自然度",这是没有 dyadic GT 时最强的证据。
4. **多轮语义连贯 + 临床真实性**:LLM-judge + 专家评,建"数字患者"专属维度。
5. **(长期)dyadic GT**:若能录到双人对话数据,解锁 rPCC 反应性 + 训练效能实验。
