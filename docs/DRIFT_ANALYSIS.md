# Avatar 漂移/变形 — 根因分析 · 当前缓解 · 局限

> 聚焦一个问题:**为什么长时间生成时 avatar 会漂移/变形,我们目前怎么管理它,还差在哪。**
> 面向:进度汇报 + 自己吃透技术细节。日期 2026-07-01。
> 配套:系统全貌见 [ARCHITECTURE.md](ARCHITECTURE.md);工程细节见 [AVATARFORCING_ENGINEERING.md](AVATARFORCING_ENGINEERING.md)。
> 模型论文:我们用的 [AvatarForcing 2601.00664](https://arxiv.org/abs/2601.00664);流式新版 [2603.14331](https://arxiv.org/abs/2603.14331)。

一句话:**漂移是模型的架构天花板(A),我们用"重锚"管理它并清楚它的边界(B),治本要回到架构(C)。**

---

## A. 为什么会漂移(架构根因)

### A1. 这个模型"是什么"
不是直接生成像素,而是 **block-causal 运动潜变量扩散-forcing transformer**:
- **运动潜变量**:运动自编码器把参考脸编码成"身份潜码";transformer 生成一串**运动潜码**(头姿/表情/口型);GAN 风格解码器把"身份 + 运动"渲染成 512×512。→ **身份来自参考图,运动来自 transformer。**
- **扩散-forcing**:训练时每帧独立加噪 → 支持自回归/流式逐帧去噪。
- **block-causal**:每块 NB=10 帧,因果注意力(过去 + 极小前瞻),过去存 KV cache。
- **训练视野**:N=50 帧 = **~2 秒** @25fps。
- **条件**:参考脸 + avatar 音频(→口型) + 用户音频/动作(→反应),CFG 用 `a_cfg`(音频)、`u_cfg`(反应)。

### A2. 漂移的三个成因 ⭐
1. **曝光偏差(exposure bias)**:每块生成后写进 KV cache 当"事实"给后续块做条件;但生成帧有微误差 → 误差一步步复合。**模型每块只生成一次、永不回看修正**,没有纠错环节。
2. **训练 2 秒、却跑几分钟**:远超训练分布,没有任何机制把它拉回"训练时见过的样子"。
3. **无"回正"约束**:生成模型即使输入静止也会自编微运动,且**没有回到中性的约束** → **单向累积**(→ 头总往左偏、眼神总朝斜上,是漂移的方向性偏置,不是在反应你)。

> ⚠️ 关键澄清:KV cache 是**有界滑动窗口**(cache_len=40≈1.6s,老帧会滚出)。漂移**不是**缓存无限堆积,而是**自回归轨迹属性**——每步偏一点往前传,窗口里的"近期历史"本身已漂,所以有界也拦不住。**重锚就是把这条轨迹拉回干净起点。**

### A3. 怎么表现成"糊/扭"
漂移体现在**纹理(变糊)、头姿(转头)、眼神(乱看)**,并有**级联放大**:
> 自回归微漂 → 姿势漂到**模型很少见的大角度(OOD)** → GAN 解码器在该姿势没训练好 → **当场扭曲/融化**。

推论(和实测吻合):
- **换男生图更糊**:深肤色/炸开头发是高频细节,偏离正脸时更难稳;参考图越 OOD 越早崩。
- **说话/倾听都漂**:倾听 `u_cfg` 高→自编运动大→漂得快;说话 `u_cfg=0`→运动小但仍慢漂。

### A4. 论文证实是固有的 + 新论文的"正解"
- 2601 **全文不讨论长程稳定、无防漂移机制**,明说为"有界交互短片段"设计 → **架构天花板,不是 bug**。
- 2603(流式)正解两招,正好补上成因:
  1. **滑窗未来去噪**:同时对未来 L 块异质噪声去噪,**每块定稿前被反复精修 L 次** → 治成因①;
  2. **dual-anchor**:style anchor(参考帧 pre-RoPE、每步重映射位置)+ temporal anchor(复用最近干净块) → 治成因③。
  - 消融:**加大未来窗口 L 比加去噪步数更提稳定** → 稳定来自"前瞻+精修",不是算力。

## B. 目前怎么解决(缓解手段)

### B1. 核心:重锚(re-anchor)⭐
**思想**:模型只在短片段内稳定,那就**周期性"重开一局"**,别让连续生成超出训练视野。
**机制**:定期调 `begin_live()` → ① 重新编码干净参考脸 ② 清空 KV cache(丢弃漂移历史) ③ 位置归零 → 把漂了的轨迹**强制拉回干净起点**,变形瞬间消失。
**门控**:只在 Jordan 真静默时触发,绝不在说话中途重锚(否则打断)。

### B2. 让重锚不突兀
- **溶解过渡(cross-fade)**:重锚那下把"漂移脸 → 干净参考脸"做 8 帧(~0.32s)线性像素混合渐变(电影叠化),盖住跳变。
- **缩短间隔(→12s)**:漂移未累积多就刷,两端更接近,溶解更顺、跳变更小。二者配合。

### B3. 两个可调杠杆
- **`u_cfg`(反应强度)**:调低→自编运动小→漂得慢。代价:反应变弱。**"稳定↔反应"的根本权衡旋钮。**
- **参考图质量**:选正脸、平视、光照均匀、头发不炸的 in-distribution 脸(simli.png 稳,jordan.png 糊)。

### B4. 试了没用的:context_noise(有价值的负结果)⭐
借新论文的 `context_noise`——往写回 cache 的历史注噪,想让模型"别全信历史"。**实测没用**。且查到**他们推理时 context_noise=0** → 证实稳定不是靠推理期注噪,而是靠架构(未来窗口精修)。**结论:只搬噪声、不搬架构,搬不过来稳定性。** 这条排除了一整个方向。

### B5. 相关旋钮索引(env)
| 变量 | 默认 | 作用 |
|---|---|---|
| `AF_REANCHOR_S` | 12 | 重锚间隔(秒),0=关 |
| `AF_XFADE` | 8 | 重锚溶解过渡帧数(~0.32s),0=关 |
| `AF_U_LISTEN` | 1.0 | 倾听反应强度(↓ 更稳、反应更弱) |
| `AF_U_SPEAK` | 0.0 | 说话时反应强度 |
| `AF_FACE` | data/simli.png | 参考脸 |
| `AF_CTX_NOISE` | 0 | (已弃用)上下文注噪,实测无效 |

## C. 局限 / 不足(诚实清单)⭐

1. **是"管理"不是"治愈"**:模型照样漂,只是不停重置,底层不稳定性没动。
2. **重置本质不自然**:再溶解,"每隔几秒姿势弹回中性"都不是真人行为。
3. **门控很脆**:太严→几乎不触发(实测一整轮才 1 次,漂移失控);太松→重置太频、begin_live 停顿多可能卡。难 robust 调。
4. **重置丢反应上下文**:begin_live 清 KV cache,最近几秒"反应记忆"没了,连续性每次断一下。
5. **说话模式覆盖差**:重锚只在静默触发,一段长说话内部就能漂,没法说到一半重置。
6. **依赖参考图**:对"脸有多 in-distribution"敏感,不是"任何脸都稳"的鲁棒方案。
7. **和 novelty 冲突**:降 `u_cfg` 治漂移 = 削弱反应式倾听,而反应正是核心贡献。**稳定和反应本质在打架。**
8. **真·根治在架构层**(换流式模型 / 加姿势正则),尚未做——重锚只是它的粗糙近似。

## D. 治本方向(下一步)

1. **换底座到 2603 流式模型**(有未来窗口精修):但它纯音频、无反应通道,要**加一路用户动作条件 + 重训** → 研究工作,非配置。
2. **引擎内加"姿势回正正则"**:每步把生成运动潜码轻微往参考姿势拉,从源头压单向漂移,**无需可见重置**。中等工程,收益不确定。
3. **"反应式 + 长程稳定"同时做到,是 neither paper 有的空位 → 可发表的贡献点。**
